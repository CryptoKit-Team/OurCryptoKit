Our Security Practices

Every layer of CryptoKit is engineered with defense-in-depth — from network to application to human factors.

End-to-End Encryption

All data in transit is protected with TLS 1.3. Data at rest is encrypted using AES-256-GCM with envelope encryption and HSM-backed key management.

TLS 1.3AES-256HSM

Zero-Knowledge Architecture

Your encryption keys, plaintext data, and passwords never reach our servers. All cryptographic operations run client-side in your browser via Web Crypto API.

Client-sideWeb CryptoNo logs

Authentication & Access

Passwords are hashed with Argon2id. We offer TOTP/WebAuthn MFA, session management, IP allowlisting, and role-based access controls (RBAC).

Argon2idWebAuthnRBAC

Infrastructure Security

Hosted in SOC 2 Type II certified data centers with DDoS protection, network micro-segmentation, intrusion detection systems (IDS), and immutable infrastructure via IaC.

SOC 2IDS/IPSDDoS

Continuous Monitoring

24/7 SIEM-based monitoring with real-time threat detection, automated alerting, anomaly detection on all API endpoints, and quarterly penetration testing by independent firms.

SIEMPen Testing24/7

Secure Development (SDLC)

Every code change undergoes SAST/DAST scanning, peer review, dependency auditing via SCA tools, and container image signing before deployment to production.

SASTDASTSCA

Vulnerability Disclosure

We appreciate security researchers who help keep CryptoShield safe. If you discover a vulnerability, please report it responsibly:

  • Email security@cryptoshield.com with PGP encryption
  • Include detailed steps to reproduce the issue
  • Provide proof-of-concept code or screenshots
  • Allow up to 90 days for coordinated disclosure
  • Do not access, modify, or delete other users' data
  • Do not perform DoS/DDoS or social engineering attacks
Incident Response

Our Response Protocol

When a security event is detected, our team follows a battle-tested incident response plan.

T+0 MINUTES

1. Detection & Triage

Automated SIEM alerts trigger our on-call security engineer. Initial severity assessment using CVSS 3.1 scoring within 15 minutes.

T+30 MINUTES

2. Containment

Affected systems are isolated, compromised credentials are revoked, and network-level blocks are deployed. War room is assembled for critical incidents.

T+1 – 4 HOURS

3. Investigation & Analysis

Root cause analysis performed using immutable audit logs, memory forensics, and network packet captures. Attack vector and blast radius are fully mapped.

T+4 – 24 HOURS

4. Eradication & Recovery

Vulnerability is patched, affected infrastructure is rebuilt from known-good images, and service integrity is verified before full restoration.

T+24 – 72 HOURS

5. Notification & Disclosure

Affected users are notified per GDPR timelines. A public post-mortem is published with technical details, lessons learned, and preventive measures.

T+7 – 30 DAYS

6. Post-Incident Review

Blameless retrospective conducted. Runbooks are updated, detection rules tuned, and findings are fed back into our secure SDLC and training programs.
