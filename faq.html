❓ FAQ

Frequently Asked Questions

Answers to the most common questions about CryptoKit.

📑 On This Page

    General Questions

    Is CryptoKit really free?

    Yes! CryptoKit is 100% free and open source under the MIT license. No hidden fees, no premium tiers, no advertisements.

    Where is my data stored?

    Nowhere. All cryptographic operations happen in your browser using the Web Crypto API. We never see, log, or store your data on our servers.

    Can I use CryptoKit offline?

    After first load, most tools work offline since they run entirely in your browser. You can also download the source code and run it locally.

    Is it safe to encrypt sensitive data here?

    Yes, for personal use. However, for enterprise or life-critical applications, we recommend using audited, certified solutions or professional-grade key management systems.

    Algorithm Questions

    Which algorithm should I use?

    For most use cases:

    • Hashing: SHA-256
    • Encryption (symmetric): AES-256-GCM
    • Encryption (asymmetric): RSA-2048 or ECC P-256
    • Passwords: Argon2 or bcrypt
    • Digital signatures: Ed25519 or ECDSA

    Why isn't MD5 recommended?

    MD5 is cryptographically broken. Attackers can create two different files with the same MD5 hash (collision attack). Use SHA-256 or better for any security-critical work.

    How do I import keys from other tools?

    CryptoKit accepts standard PEM and DER formats. Copy-paste your PEM key (including the -----BEGIN----- and -----END----- lines) into the input field.

    Usage Questions

    Can I use these tools commercially?

    Yes! The MIT license allows commercial use, modification, and distribution. Just include the original copyright notice.

    How can I contribute?

    Visit our GitHub repository, fork the project, and submit pull requests. We welcome bug fixes, new features, and documentation improvements.

    I found a bug. What should I do?

    Please open an issue on our GitHub repository with:

    • Browser and version
    • Steps to reproduce
    • Expected vs actual behavior
    • Screenshots if applicable

    Security Questions

    Are these tools quantum-resistant?

    Currently no. RSA and ECC are vulnerable to future quantum computers. Post-quantum algorithms are being standardized by NIST. We plan to add support once they're ratified.

    Are there any backdoors?

    Absolutely not. Our code is open source — you can audit every line yourself. We use standard Web Crypto API implementations only.
