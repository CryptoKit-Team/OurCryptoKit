Inspect an EC key

Paste a PEM public or private elliptic-curve key (ECDSA or ECDH). This decodes the curve, coordinates, and — for private keys — the raw secret scalar.

Run a real ECDH key exchange

Alice and Bob each generate their own key pair, exchange only their public keys, and independently derive the same shared secret — without ever transmitting it.

Alice

Public key (x, hex, truncated)
Derived shared secret (SHA-256 of raw bits)

Bob

Public key (x, hex, truncated)
Derived shared secret (SHA-256 of raw bits)
This is the core idea behind TLS, Signal, and WireGuard. Neither party ever sends their private key or the shared secret itself — an eavesdropper who sees both public keys still can't compute the shared secret (the Elliptic Curve Diffie-Hellman problem). In production, the raw shared secret is passed through a KDF (like HKDF) before being used as an encryption key.

ECDSA signing across curves

Sign the same message with different curve/hash combinations and inspect the raw (r, s) signature components.

Visualize the curve equation

Every elliptic curve used in cryptography follows the short Weierstrass form y² = x³ + ax + b. This plots it over real numbers (not the actual finite field used in ECDSA) so the shape and point addition are easy to see.
