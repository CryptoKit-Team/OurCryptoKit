🧠 Core Concepts

Cryptography Fundamentals

Understand the core concepts that power all cryptographic operations.

📑 On This Page

    What is Cryptography?

    Cryptography is the practice and study of techniques for secure communication in the presence of adversaries. It transforms readable data (plaintext) into unreadable data (ciphertext) that only authorized parties can access.

    ℹ️
    Origin
    The word "cryptography" comes from Greek: kryptós (hidden) + graphein (to write).

    Symmetric vs Asymmetric Encryption

    Symmetric Encryption

    Uses the same key for both encryption and decryption. It's fast but has a key distribution problem — how do you share the key securely?

    • Examples: AES, DES, ChaCha20
    • Speed: Very fast
    • Best for: Encrypting large amounts of data

    Asymmetric Encryption

    Uses two different keys — a public key (shared openly) and a private key (kept secret). Data encrypted with one can only be decrypted with the other.

    • Examples: RSA, ECC, ElGamal
    • Speed: Slower
    • Best for: Key exchange, digital signatures

    Hashing vs Encryption

    A common source of confusion! Here's the key difference:

    FeatureHashingEncryption
    DirectionOne-wayTwo-way (reversible)
    Key NeededNoYes
    Output SizeFixedVariable
    Use CaseVerify integrity, store passwordsProtect confidentiality
    ExamplesSHA-256, MD5AES, RSA

    Public Key vs Private Key

    In asymmetric cryptography, you have a key pair:

    🔓 Public Key

    • Can be shared with anyone
    • Used to encrypt data or verify signatures
    • Typically distributed openly

    🔐 Private Key

    • Must be kept absolutely secret
    • Used to decrypt data or create signatures
    • Never share this — anyone with it controls your identity!
    ⚠️
    Critical Warning
    If your private key is exposed, all data encrypted for you can be decrypted, and someone can impersonate you. Store it safely!

    Digital Signatures Explained

    Digital signatures prove that a message came from a specific person and hasn't been altered. They work like this:

    1. Signer creates a hash of the message
    2. Signer encrypts the hash with their private key → signature
    3. Recipient decrypts the signature with signer's public key
    4. Recipient compares the decrypted hash with their own hash of the message
    5. If they match → the signature is valid ✅

    Salt, IV, and Nonce

    These are all random values used in cryptography, but they serve different purposes:

    Salt

    A random value added to a password before hashing. Prevents rainbow table attacks.

    Example 
    password: "hunter2"
salt: "x9k$mP2q"
hash(password + salt) = "a3b7c2d..."

    IV (Initialization Vector)

    Random value used in block cipher modes (like AES-CBC). Ensures that encrypting the same message twice produces different ciphertexts.

    Nonce (Number Used Once)

    Similar to IV but must never be reused with the same key. Common in AES-GCM.
