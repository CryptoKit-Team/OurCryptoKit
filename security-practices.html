🛡️ Security

Security Best Practices

Learn how to use cryptography safely and avoid common security pitfalls.

📑 On This Page

    Key Management

    The most common cryptographic failures come from poor key management, not weak algorithms.

    Never Reuse Keys or IVs

    Reusing an IV with the same key can completely break your encryption. Always generate a fresh random IV for each message.

    🚨
    Critical
    Reusing an AES-GCM nonce with the same key allows complete decryption. Always use unique nonces!

    Store Private Keys Securely

    • Use hardware security modules (HSM) when possible
    • Never store keys in source code or version control
    • Use environment variables or secret managers
    • Encrypt keys at rest with a master key

    Password Security

    Use Strong Passwords

    • Minimum 16 characters
    • Mix of uppercase, lowercase, numbers, symbols
    • Never reuse passwords across sites
    • Use a password manager

    Hash Passwords Properly

    Never store passwords in plain text or use fast hashes like SHA-256 directly:

    ❌
    Wrong
    sha256(password) — Vulnerable to rainbow tables and brute force
    ✅
    Correct
    Use Argon2, bcrypt, or scrypt with a unique salt

    Signature Verification

    Always verify signatures before trusting data. Never assume a signature is valid.

    Choose Modern Algorithms

    ✅
    Recommended
    AES-256-GCM, RSA-2048+, ECDSA P-256, SHA-256+, Argon2
    ❌
    Avoid
    MD5, SHA-1, DES, 3DES, RC4, ECB mode, RSA without OAEP padding

    Rotate Keys Regularly

    Even the strongest keys should be rotated periodically:

    • Encryption keys: Every 1-2 years
    • Signing keys: Every 2-3 years
    • API keys: Every 90 days
    • Session keys: Every session

    Always Use HTTPS

    Never transmit sensitive data over unencrypted connections. Use TLS 1.3 when possible, TLS 1.2 as minimum.

    Common Mistakes to Avoid

    • ❌ Rolling your own crypto
    • ❌ Using outdated algorithms (MD5, SHA-1, DES)
    • ❌ Hardcoding keys in source code
    • ❌ Using ECB mode for encryption
    • ❌ Storing passwords in plain text
    • ❌ Reusing nonces or IVs
    • ❌ Ignoring signature verification failures
    • ❌ Using non-cryptographic random (like Math.random())
